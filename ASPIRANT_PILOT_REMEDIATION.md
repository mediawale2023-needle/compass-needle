## Phase 1 implementation and security contract

- MP and Admin JWTs must contain `sub`, `tid`, `role`, `iat`, `exp`. Compare tenant and role with current DB state on each authenticated request, reject suspended accounts/disabled tenants, and fail closed on unreadable revocation state. Existing correctly issued login tokens retain their format; malformed legacy tokens need reauthentication.
- Password changes/resets, staff role/reassignment/suspension, team deactivation account deletions and tenant live-state transitions write token cutoffs within the same transaction. A failed revocation rolls back the associated change. Login timestamps bind to the beginning of authentication so a concurrent revocation cannot be bypassed by minting later.
- Interpret naive stored dates as UTC; accept typed PostgreSQL and ISO SQLite dates. Do not infer epoch timestamps using the host local timezone.
- WebSocket authorization uses the same checks at connection, before inbound actions and outbound frames, and at one-second idle intervals. A request already authorized before a revocation commits is not retroactively rolled back. Direct SQL authority edits outside the provided mutators must write revocation state too if old tokens must remain invalid after authority is restored.
- Legacy NULL `is_active` values retain prior compatibility and are treated as active; explicit false/0 is rejected. This does not certify legacy account hygiene. No migration or production data change is included.
- Support requires an active, unexpired, consumed request bound to its tenant, target, approver and current active Admin operator. Operator/target revocation since request creation invalidates it. End/revoke/expire immediately denies subsequent requests. Conditional updates prevent launch races and state resurrection.
- `full_view` now means the reviewed passive-read allowlist: GET auth/me, dashboard summary/overview, cases/list/detail/activity, profile, team and staff; POST support-access/end is the sole allowed control action. Other endpoints, mutations and live-browser WebSockets are denied. Each allowed request records the actual operator and request/tenant/path, without citizen payloads. Ending support does not revoke the owner's normal login.
- Existing Admin visuals and aspirant layout remain unchanged apart from support-banner wording that explicitly explains read-only restrictions. This is intentionally not full owner impersonation; ancillary dashboard tools can return 403 for support sessions.
